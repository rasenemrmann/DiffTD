# Tasks: TouchDesigner Version Control (DiffTD)

**Input**: Design documents from `/specs/001-td-version-control/`

**Prerequisites**: plan.md, spec.md, research.md, data-model.md, contracts/, quickstart.md

**Tests**: Included. The constitution (Development Workflow) requires automated tests for schema, determinism and round-trip behavior, run outside TD where possible with shared fixtures.

**Organization**: Grouped by user story (US1–US6, spec priorities P1–P6) so each is independently testable.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: Can run in parallel (different files, no dependencies on incomplete tasks)
- **[Story]**: US1–US6, only on user-story phase tasks
- All paths are relative to the repository root

## Path Conventions

Multi-part layout from plan.md: `schema/`, `difftd/` (TD-side Python), `viewer/` (static web app), `hooks/` (shell), `tests/{python,js,hooks,fixtures}`.

## Dependencies & Execution Order

### Phase Dependencies

- **Setup (1)** → **Foundational (2)** → user stories → **Polish (9)**
- **US1 (3)** and **US3 (5)** depend only on Foundational and can run in parallel.
- **US2 (4)** needs US1's `exporter.py` for the round-trip test (T028) but can start `importer.py` earlier.

- **US5 (7)** needs US1 (export for unsaved-edit detection) and US2 (import).
- **US6 (8)** needs US3, US4, and US5 (reload endpoint) — its merge logic (T058, T060) only needs Foundational and can start earlier.

### Within Each Story

Tests first (must fail), then modules, then UI/TD wiring, then the quickstart run for that story.

### Parallel Opportunities

- Setup: T002, T003, T004
- Foundational: T006/T007/T008 (fixtures), then T010, T013, T015 (tests) in parallel with unrelated implementation
- US1 tests T017/T018; US2 tests T027/T028; US3 T033/T034 and T035/T036; US4 T043/T044; US5 T050/T051 and T055; US6 T058/T059
- Two developers: one on the TD side (US1 → US2 → US5), one on the viewer side (US3 → US4 → US6 merge logic), meeting at US5/US6 integration.

## Implementation Strategy

### MVP First (User Story 1 only)

1. Phases 1–2, then Phase 3. Stop and validate with quickstart step 2: projects are now diffable in plain Git.
2. Demo before continuing.

### Incremental Delivery

1. + US2: rollback capability.
2. + US3: visual review (usable by teammates without TD).
3. + US4: no-upload review.
4. + US5: hands-free reload.
5. + US6: full parallel-work workflow.

### Risks to watch

- TD API differences (T019/T020 first thing in US1; may change T021–T023).
- Browser access to local folders is Chromium-only (documented, file mode as fallback).
- No opdiff prototype is in the repo (research R14): T037–T041 build the UI from the contracts.
